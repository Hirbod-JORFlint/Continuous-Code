# Cline lifecycle hooks (generated)

Generated by `opc/scripts/harness/gen_cline.py` from the neutral manifest
`harness/lifecycle/hooks.toml`. Experimental.

Cline hooks are real executable scripts (since v3.36): each hook reads one JSON
object on stdin and returns JSON controlling the session (`cancel`,
`contextModification`). These files forward the Cline stdin payload straight
into the neutral python hooks in `harness/lifecycle/hooks/`; the shared
payload adapter (`_payload.py`) understands the Cline field naming.

## Naming (platform-specific)

- Windows: `HookType.ps1` is the only supported form. Hook discovery ignores
  any other name; on Windows hooks run whenever the file exists (no toggle).
- macOS/Linux: extensionless executable named exactly `HookType`. Rename these
  files and `chmod +x`. Enable/disable each hook in the Cline UI (Hooks tab).

## Coverage

| Hook file        | Neutral events forwarded                    |
| ---------------- | ------------------------------------------- |
| `PostToolUse.ps1` | post-tool-use-tracker, braintrust-post-tool-use |
| `PreCompact.ps1` | pre-compact-continuity |
| `TaskComplete.ps1` | auto-handoff-stop, braintrust-stop |
| `TaskStart.ps1` | braintrust-session-start, session-symbol-index, session-start-continuity |
| `UserPromptSubmit.ps1` | premortem-suggest, braintrust-user-prompt-submit |

## Caveats

- Cline hook files filter by UI toggle, not by per-tool matcher. A manifest `matcher`
  (e.g. `Edit|Write`) is therefore NOT enforced by Cline's PreToolUse/PostToolUse hooks;
  the forwarded hook must tolerate every tool (they do, via `_payload.py`).
- `contextModification` output from Cline hooks is currently passed through verbatim as
  `cancel:false` (the neutral hooks are advisory). Wire structured output in Step 8.
- Hooks resolve `~/.opc/hooks/hook_launcher.py`; create the `~/.opc/hooks` junction, or
  set `OPC_PROJECT_DIR` and rely on the launcher's canonical-directory search.
